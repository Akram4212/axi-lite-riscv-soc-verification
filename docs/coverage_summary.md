# Coverage Summary

## Overview

The project uses complementary coverage methods:

1. Python functional coverage for AXI-Lite transactions and peripheral behavior.
2. Verilator RTL line and branch coverage for RV32I block-level regressions.
3. Merged Verilator coverage across full-SoC firmware workloads.

Coverage is interpreted by verification level. Unit regressions provide detailed instruction and corner-case coverage, while firmware regressions measure realistic integrated execution.

## Full-SoC Firmware Coverage

Merged Verilator coverage was collected across five firmware workloads:

- `start`
- `memory_test`
- `branch_test`
- `gpio_test`
- `timer_test`

Each workload was:

1. Assembled and linked with the RISC-V cross-toolchain.
2. Converted to a raw binary.
3. Converted to a 32-bit Verilog hexadecimal image.
4. Loaded into AXI-Lite RAM.
5. Executed by the five-stage RV32I core.
6. Checked by cocotb for correct peripheral state and absence of errors.

## Coverage Interpretation

### High-value integration coverage

The firmware suite provides strong coverage for:

- Pipeline forwarding and hazard handling
- Instruction and data traffic through the AXI-Lite adapter
- RAM byte, halfword, and word accesses
- Signed and unsigned load extension
- Branches, loops, `JAL`, and `JALR`
- GPIO register behavior
- Timer count, compare, clear, status, and IRQ behavior
- Firmware image loading and processor startup

### Paths better covered at block level

Some paths are intentionally better suited to directed cocotb tests:

- Illegal instruction encodings
- Unmapped AXI-Lite addresses
- Misaligned requests
- Read-only register writes
- Explicit `SLVERR` handling
- Backpressure combinations
- Protocol error paths

Adding artificial application firmware solely to duplicate exhaustive block-level coverage is not required.

## Reproducing the Reports

Run processor coverage:

```bash
make coverage_rv32i_core
```

Run merged full-SoC firmware coverage:

```bash
make coverage_soc
```

Generated full-SoC reports:

```text
coverage_soc/html/index.html
coverage_soc/coverage.info
coverage_soc/merged.dat
```

When an RTL-only report is generated by filtering `include/` and `tb/`, it can be stored at:

```text
coverage_soc/rtl_html/index.html
coverage_soc/rtl_only.info
```

## Current Coverage Conclusion

The combined results demonstrate:

- High block-level RV32I control and datapath coverage
- Complete decoder branch coverage
- Strong full-SoC line coverage across realistic firmware workloads
- Functional verification of the AXI-Lite subsystem and peripherals
- Complementary use of unit, subsystem, core, and integration verification

Coverage should continue to be interpreted together with assertions, directed tests, regression pass rates, and documented scope boundaries.
